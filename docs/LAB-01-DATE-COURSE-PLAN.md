# LAB-01 · 우리 둘 데이트 코스

기준일: 2026-08-18

## 목표

검색형 계산기가 아닌 **개인화 결과형 웹서비스**의 전환율과 공유율을 검증한다.

## MVP 가설

- 사용자는 긴 폼보다 한 화면 한 질문 방식에서 완료율이 높다.
- 단순 장소 목록보다 `왜 우리에게 맞는지`가 포함된 결과가 저장·공유율을 높인다.
- 특정 매장 DB 없이도 지역 + 관계 + 예산 + 시간 + 분위기 조합만으로 초기 수요를 검증할 수 있다.

## 입력

1. 지역
2. 관계 단계
3. 2인 예산
4. 데이트 시간
5. 실내/야외 선호
6. 원하는 분위기
7. 이동수단

## 결과

- 개인화 매칭 점수
- 시간대별 데이트 플로우
- 예상 예산
- 이동 방식
- 추천 이유 3개
- 작은 실행 팁
- 동일 조건 재생성
- 저장 / 공유

## 데이터 원칙

- MVP에서는 사용자 입력을 서버로 전송하지 않는다.
- 프로필과 마지막 결과는 브라우저 localStorage에만 저장한다.
- GA4/Clarity에는 선택지 범주와 행동 이벤트만 전달한다.
- 사용자가 직접 입력한 지역명 전체는 분석 이벤트 파라미터로 보내지 않는다.

## 분석

GA4:
- `date_wizard_start`
- `date_question_complete`
- `date_course_generated`
- `date_course_regenerate`
- `date_course_save`
- `share`
- `date_course_restart`

Clarity:
- 위 이벤트를 custom event로 전송
- 선택 범주는 custom tag로 설정
- 질문별 rage click / dead click / 이탈 위치 확인

## 1차 KPI

- 시작 → 결과 생성 완료율 55% 이상
- 결과 생성 → 재생성 클릭률 15% 이상
- 결과 생성 → 저장/공유 합산 8% 이상
- 모바일 질문 화면별 이탈률 확인

## 수익화 순서

1. 트래픽/완료율 검증
2. 결과 하단 네이티브 광고
3. 특정 지역 SEO 랜딩 (`성수 데이트 코스`, `비오는 날 데이트` 등)
4. 지도/실시간 장소 API 연결
5. 식당·전시·체험 제휴 링크
6. 기념일 프리미엄 코스 또는 AI 상세 플래너 실험

## 실시간 장소 연결 전 주의

현재 결과는 특정 매장의 영업시간·가격·예약 가능 여부를 보장하지 않는다. 지도/Places API를 붙이기 전에는 활동 유형과 동네 단위 추천으로 유지한다.
